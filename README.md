## :dart: O guia para alavancar a sua carreira

> CodeIgniter é um framework PHP leve, rápido e com curva de aprendizado curta: sem exigir Composer para rodar, com pouquíssima "mágica" escondida e uma documentação enxuta que explica exatamente o que cada linha faz. É a escolha de quem quer construir e manter sistemas web em PHP puro e MVC sem a complexidade de frameworks maiores, e ainda tem presença forte em sistemas legados e projetos que priorizam performance e simplicidade. Este guia reúne roadmap, documentação oficial, cursos gratuitos e pagos, canais, ferramentas do ecossistema e um capítulo sobre usar IA na prática com CodeIgniter — tudo verificado, com prioridade para conteúdo gratuito e em português.

## 🗺️ Roadmap
- [roadmap.sh — PHP Roadmap](https://roadmap.sh/php) — Guia da comunidade sobre o caminho de PHP até back-end; cita frameworks como CodeIgniter, Laravel e Symfony na etapa de "frameworks".
- [CodeIgniter4 — Releases (GitHub)](https://github.com/codeigniter4/CodeIgniter4/releases) — Histórico completo de versões do framework, com o changelog de cada lançamento.
- [Guia de upgrade (documentação oficial)](https://codeigniter.com/user_guide/installation/upgrading.html) — Como migrar um projeto entre versões do CodeIgniter 4.
- [Changelogs (documentação oficial)](https://codeigniter.com/user_guide/changelogs/index.html) — Lista de mudanças versão a versão, direto na documentação.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de PHP** — variáveis, funções, orientação a objetos básica. O CodeIgniter é amigável para quem está saindo do PHP procedural.
2. **Primeiro projeto** — instalação via Composer ou download manual, estrutura de pastas (`app/`, `public/`, `system/`), servidor de desenvolvimento (`php spark serve`).
3. **Rotas e controllers** — `app/Config/Routes.php`, controllers, roteamento automático.
4. **Views** — o motor de views nativo do CodeIgniter (PHP puro, sem template engine obrigatório) e os View Cells/Layouts.
5. **Banco de dados** — Query Builder, Migrations e Seeds para versionar o schema.
6. **Models e validação** — a camada Model do CI4 e a biblioteca de Validation nativa.
7. **Autenticação** — CodeIgniter Shield, a biblioteca oficial de autenticação e autorização.
8. **APIs REST** — Resource Controllers, respostas em JSON, filtros de autenticação.
9. **Testes** — PHPUnit integrado, testes de feature e de banco de dados.
10. **Produção** — variáveis de ambiente (`.env`), cache, segurança e deploy.

## 🚀 Por onde começar
1. **Instale o PHP** (8.1+) e, opcionalmente, o [Composer](https://getcomposer.org/) — o CodeIgniter funciona até sem Composer, mas ele facilita instalar pacotes como o Shield.
2. **Crie seu primeiro projeto** seguindo a [instalação oficial](https://codeigniter.com/user_guide/installation/index.html).
3. **Faça o tutorial oficial "Building Your First Application"** — [guides/first-app](https://codeigniter.com/user_guide/guides/first-app/index.html) — constrói um mini-site de notícias do zero, cobrindo rotas, controllers, models e views.
4. **Assista a um curso em vídeo em português** em paralelo à leitura da documentação — veja a seção [🔤 Sites e cursos](#-sites-e-cursos-para-aprender-codeigniter) abaixo.
5. **Entenda o padrão MVC no CodeIgniter** — [Model-View-Controller](https://codeigniter.com/user_guide/concepts/mvc.html) — como as três camadas se conectam no framework.
6. **Aprenda a mexer no banco** — [Query Builder](https://codeigniter.com/user_guide/database/query_builder.html) e [Migrations](https://codeigniter.com/user_guide/dbmgmt/migration.html).
7. **Adicione autenticação** — [CodeIgniter Shield](https://shield.codeigniter.com/latest/), a biblioteca oficial de login, registro e permissões.
8. **Publique um projeto** — qualquer hospedagem com PHP e Composer (Railway, Render, um VPS com Apache/Nginx) roda uma aplicação CodeIgniter sem configuração especial.

Seu primeiro projeto em poucos comandos:

```bash
composer create-project codeigniter4/appstarter meu-projeto
cd meu-projeto
php spark serve
```

## 🛠️ Ferramentas

- [codeigniter4/shield (Packagist)](https://packagist.org/packages/codeigniter4/shield) — Pacote do Shield no Packagist.
- [Padrão de code style oficial](https://github.com/codeigniter4/coding-standard) — Regras de PHP_CodeSniffer usadas no próprio framework, reaproveitáveis em qualquer projeto CI4.
- [Kint](https://kint-php.github.io/kint/) — Ferramenta de debug embutida no CodeIgniter 4 (`d()`, `dd()`), para inspecionar variáveis durante o desenvolvimento.

### Ambiente de desenvolvimento
- [Composer](https://getcomposer.org/) — Gerenciador de dependências PHP, usado para instalar o CodeIgniter e seus pacotes.
- [Laragon](https://laragon.org/) — Ambiente de desenvolvimento local para Windows (PHP, MySQL, servidor web) com configuração mínima.
- [XAMPP](https://www.apachefriends.org/) — Ambiente de desenvolvimento local multiplataforma (Apache, MySQL, PHP).
- [Xdebug](https://xdebug.org/) — Extensão de depuração e profiling para PHP.
- [DBeaver](https://dbeaver.io/) — Cliente gráfico gratuito e multiplataforma para gerenciar bancos de dados.
- [Postman](https://www.postman.com/) — Ferramenta para testar as APIs REST construídas com CodeIgniter.

### Qualidade e testes
- [PHPUnit](https://phpunit.de/) — Framework de testes usado pelo CodeIgniter 4 no seu módulo de Testing.
- [PHPStan](https://phpstan.org/) — Analisador estático de código PHP, ajuda a pegar erros antes de rodar a aplicação.

## 🤖 IA na prática
O CodeIgniter é um framework pequeno e estável, com pouca "mágica" e convenções simples — isso ajuda bastante os assistentes de IA a gerarem código correto, mas o lado oposto também é verdadeiro: por ser um framework de nicho, os modelos de IA viram muito menos código CodeIgniter em treinamento do que código Laravel ou Symfony, e é comum a IA "confundir" sintaxe do CI3 (antigo) com a do CI4 (atual), ou sugerir padrões de outro framework PHP sem perceber.

**Para aprender**
- Peça para a IA explicar a diferença entre um método de Controller do CI3 e do CI4 quando encontrar exemplos antigos na internet — a sintaxe mudou bastante entre as duas versões.
- Peça exercícios criando um CRUD simples (Model + Controller + View) sobre o tópico que está estudando: você escreve a solução, pede para a IA revisar.
- Use a IA para explicar uma mensagem de erro do Query Builder ou de uma Migration antes de sair copiando a correção sem entender.
- Peça para transformar uma query SQL solta em Query Builder do CodeIgniter, e explique por que a versão com Query Builder é mais segura contra SQL injection.

**Para trabalhar**
- Use GitHub Copilot, Cursor ou Claude Code para gerar Controllers, Models e Filters a partir da estrutura do projeto — sempre revisando o código gerado, porque a IA erra com mais frequência em frameworks de nicho como o CodeIgniter.
- Cole trechos da [documentação oficial](https://codeigniter.com/user_guide/index.html) no contexto do assistente antes de pedir código: como o CodeIgniter tem pouco material de treino comparado a frameworks maiores, dar o contexto certo reduz bastante a alucinação de métodos que não existem.
- Depois de aceitar uma sugestão que mexe no banco, **leia** a Migration gerada antes de rodar `php spark migrate` — IA pode gerar migrations com `dropColumn` ou `dropTable` desnecessários.
- [GitHub Copilot](https://github.com/features/copilot) — Autocomplete e chat com IA no editor; gratuito para estudantes e com plano free.
- [Cursor](https://cursor.com/) — Editor baseado no VS Code com IA integrada ao fluxo de trabalho.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: útil para explicar e revisar Migrations, Controllers e queries do CodeIgniter.

**Limites e boas práticas**
- IA **confunde CI3 com CI4** com frequência — sempre confira o método sugerido na [documentação oficial do CI4](https://codeigniter.com/user_guide/index.html), não em tutoriais antigos de CI3.
- Desconfie de código que monta SQL "na mão" com concatenação de strings em vez de usar o [Query Builder](https://codeigniter.com/user_guide/database/query_builder.html) — é o padrão de SQL injection mais repetido por IA.
- Nunca aceite sugestões que exponham credenciais de banco no `.env` versionado ou desativem a proteção CSRF nativa do framework sem necessidade real.
- Migrations geradas por IA precisam ser lidas por um humano antes de rodar em produção — reverter uma migration aplicada num banco com dados reais pode ser destrutivo.

## 💼 Carreira e vagas
CodeIgniter aparece com menos frequência que Laravel nas vagas brasileiras de back-end PHP, mas ainda é comum em sistemas legados, projetos de agências e produtos que priorizam simplicidade. Dica: nos repositórios e grupos de vagas abaixo, pesquise por "PHP" (CodeIgniter raramente é filtro isolado, mas aparece nas descrições).
- [backend-br/vagas](https://github.com/backend-br/vagas) — Vagas de back-end no Brasil (PHP incluso) publicadas como issues no GitHub.
- [PHP Brasil Vagas (Telegram)](https://t.me/phpbrasilvagas) — Grupo da comunidade PHP Brasil dedicado a divulgação de vagas.
- [RemoteOK — vagas PHP](https://remoteok.com/remote-php-jobs) — Vagas remotas internacionais filtradas por PHP.
- [WeWorkRemotely — vagas de programação](https://weworkremotely.com/categories/remote-programming-jobs) — Agregador de vagas remotas internacionais, com filtro de PHP na busca.
